# Codex 连续观影

影院操作与登录见[观众指南](../工具准备/Codex%20App%20Server.md)。适配器需要支持 `turn/start.toolOutput` 的本机 Codex CLI。影院用标准输入输出启动 Codex app-server，并为每场放映保存独立聊天。恢复同一场放映时继续使用已绑定的账号、观影档案、模型和聊天。

两种账号模式的新聊天都以「片名 · YYYY-MM-DD HH:mm:ss」命名，时间取房间实际开启的本地时间。恢复放映时保留当前聊天名，包括观众手动改过的名字。

新聊天使用名为 `cinema` 的工作目录，既有聊天继续使用原来的目录。

沿用本机 Codex 登录并已安装 Codex 桌面端时，影院在首次创建并保存观影聊天后尝试用桌面端打开 `cinema` 工作区。后续放映仍在同一个工作区创建各自的聊天。独立登录的聊天保存在影院自己的 Codex 登录目录中。

沿用本机 Codex 登录时，新开或恢复的聊天使用本机 Codex 在影院聊天目录生效的沙箱或权限档案及审批策略。修改本机配置后，重新连接连续观影即可在同一条聊天应用配置。影院窗口目前不提供手动审批。影院独立登录使用只读沙箱，审批策略为 `never`。

Codex 通过原有的 `open_watch_cinema_tick` 结果接收影片进度、对白、声音、分镜和观众消息。已播放的影片达到设定间隔时触发。暂停期间有观众消息才唤醒对话，播放中的新消息可以进入当前 Codex 轮次。已经排队的常规影片内容随下一次交付一起到达。

影院里的回复、回看分镜和手记沿用该放映自己的 MCP 连接。观众只能在影院收到由 `cinema_post_message` 发布的消息。影片跳转后停止处理旧播放位置的轮次，房间结束时断开跟片。

沿用现有 Codex 时保留已经配置的其他集成，影院工具统一使用该房间的连接。两种模式都可以在影院编辑观影指令。默认和自定义指令都支持 `{{viewerName}}`。开房或重连时，桥接读取「名字与档案」里当前的观众昵称，渲染本场保存的指令模板，再写进影院工作目录的 `AGENTS.md`。每场放映可填写一段观众开场白，放在首个正常送达 Codex 的播放结果前面。播放前的房间消息照常送达。恢复同一场放映时，已送过的开场白会留在该场聊天里。

观众选择从同一部影片上次结束的位置继续时，新房间的第一次播放交付会在观影内容前说明续看时间，并附上完整的影片共用手记。有开场白时开场白排在最前。播放前的暂停留言照常送达。重新连接同一房间时，已送达的开场白和续看手记不会重复附上。支持分页读取轮次的 app-server 可以从最近一轮恢复尚未保存的送达记录。
