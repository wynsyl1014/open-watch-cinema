# 现有功能

更新日期为 2026-11-23。

## 一起看电影

银幕边的齿轮 →「影院设置」→「观影指南」打开与 GitHub 相同的[观影指南](../观影须知/观影指南.md)。机器环境、安装命令与故障排查见[安装与排错](../工具准备/安装与排错.md)。

影院播放本地影片，观影准备生成带时间的画面、对白和声音资料。AI 通过 MCP 接收这些资料，在共享房间发送消息。影片及声音模型分析在本地进行，MCP 向连接的 AI 发送文字和图片。

`open_watch_cinema_tick` 把已经播放的内容按电影时间整理成文字和真实 JPEG 图片，包含对白、声音描述、简短动态说明及房间消息。普通 MCP 客户端由宿主主动调用。Codex App Server 和 ChatGPT Listener 由 Watch Bridge 按播放进度或房间新消息发起交付。未接全的内容与迟到的声音描述由后续 tick 补齐。暂停期间仍可接收房间消息。

影院设置管理参与者的名字与观影 AI 档案。每个 MCP 连接继承接入时选中的档案，独立保存房间、交付进度和图片引用。切换档案用于接下来的连接。切换房间或拖动播放器时，观影进度按当前播放位置衔接。

房间底部与侧栏输入框的互动按钮旁提供「＋」快捷消息入口，点选条目可将预设话术追加填入当前输入框（保留已有输入内容，方便一起发送）。默认自带一条「整理观影手记」提示词，可在 **影院设置 → 快捷消息** 修改、恢复默认，或新增、编辑、删除自定义条目，数据保存在本地影院数据库的 `settings` 表（`GET / POST /api/quick-messages`）。

### 连接状态与调用记录

放映页按档案和具体 MCP 连接展示在线情况。工具结果由适配器单独上报，按块保留文本、图片及其原始顺序；浏览器展开某次调用时才请求详情和图片。查看记录不会重新调用模型或改变影片进度。成功 tick 的交付时间与连接和房间绑定。

活动存储使用本次影院服务独占的临时 SQLite 库，大结果按内容块保存，记录不会进入影片数据库或观影包。关闭服务会释放临时库。只传摘要的异常大结果会在时间线上标明详情不可用。

### 接着上次的位置看

结束房间后重新为同一影片开房，若该片最近一场放映留下了播放进度，可以选「从 14:25 继续」或「从头看」。两种选择都会开一场新房间，播放器停在所选位置，按播放后开始。启用自动观影时可在同一弹窗填写本场开场白。手动续看开房成功后可编辑和复制本次的 MCP 提示词，也可直接关闭弹窗，之后按播放继续。常用的续看模板可在「影院设置 → 连接 AI → MCP 客户端」保存为本机默认。

## 画面与画质

新影片使用 v3 观影包，每片记录自己的画面配置。新准备的三个档位都从原片取样，在内存处理，保存播放时交给 AI 的成品分镜。

观影准备按影片选择经济、均衡或完整档。经济按保留时刻拼接 221 × 124 的全景小格，均衡使用 268 高的全景和同尺度变化局部，完整档按动作送出最高 480p、720p 或 1080p 的独立全景。观影工具直接读取该包准备好的图片。三个档位共用动作筛选，按画面结构略过纯色空场，对可能省去的相似画面回原片以每秒 8 帧复核动作。可辨认的文字和轮廓优先保留。完整档进一步核对高清差异，直接从对应时刻的原片裁出细节，放大后嵌入空位或单发。均衡和完整在制包时把成对角标画入全景和对应局部。开场提示一次，随后只显示时间。各档实图见[画质参考](../观影须知/画质参考.md)。单张故事板上限为 1,572,864 字节。

均衡和完整档沿用当前 5 分钟制包分段内待写的全景。后续时间组补交新动作和切镜，复查后没有新变化的组可以省去图片。当前组距离全景超过 15 秒或进入下一分段时，重新建立全景。三帧同向平稳摇镜在短窗复查后保留起止，起点已经交付时只补终点。画中画在四角与四边中点寻找空位，避开人脸、文字和动作。均衡档同组需要单发的多个局部横拼为一张图。完整档的 480p、720p 或 1080p 全景独立成图，局部通常放大 1.6 倍，空间紧张时尝试以 1.1 倍嵌入，并优先保护密集线条。

新制包和换档都沿用已有的分镜触发原因。均衡档对距离上一张展示画面不超过 3.5 秒的切镜组，用候选缩略图核对本组末帧和上一张画面。末帧与独立中插镜头继续交付。对候选跨度不超过 2.5 秒的组，也通过缩略图省去同镜头的过渡全景。局部变化继续和各自的全景配对。这一步只读取候选图，不做额外的视频复查。

完整档在同样的 3.5 秒切镜窗口内，仅略过与上一组末次展示或本组末帧同镜头、且缩略图与高清原片均无明显变化的前置画面。独立中插、明显局部变化和高清微细节继续交付。完整档保留短动作组的动作过程。

`cinema_inspect_frame({ atMs })` 用图注里的时间重读已经收到的成品分镜。完整档的放大局部随画面送达。旧 v2 包提供高清细看提示时，可以加 `quality: "hd"` 从原影片取帧。

图片获取耗时见[实验记录](实验记录.md)。

## 跳过片头、片尾和中间片段

新制的经济、均衡、完整观影包都可跳过片头、片尾和自定义中间片段。影片默认继承所在合集的配置，单片保存自己的配置后整份覆盖。准备只分析保留区间的画面和音频，对白及歌词按字幕开始时间过滤。断点续做和换档沿用原包的区间记录。没有跳过记录的旧包按原样播放和交付。

在「影片设置 → 跳过片段」填写片头、片尾和任意多个中间时段。片尾结束时间留空时跳到片尾。进入合集后，顶部的「默认跳过片头片尾」可保存合集区间。影片设置会显示继承的区间，可以直接编辑，保存后作为本片配置。勾选「使用文件夹默认」并保存可恢复继承。已有观影包时，编辑后需重新准备观影包才能应用新配置。

「影院设置 → 观影准备 → 跳过片头片尾」控制开包前的未填提醒。开启后，点「准备观影包」且当前生效区间为空时，可以选「去填写」进入影片设置，或选「继续整片准备」。关闭提醒时，已保存的跳过区间照常使用。

顺播进入跳过区间时，播放器跳到该段结束，并同步位置给房间和 AI。手动拖到区间内时可以照常观看，包括拖到起点。拖回区间之前再次顺播，或播出该区间后再顺播进入，会恢复自动跳过。已有包使用包内区间，尚未制包时使用影片当前生效配置。

AI 在播放头进入包内跳过区间时收到一次提示，中间片段使用影院当前的观众名，同一区间停留期间只提示一次。开包前的未填提醒开关只影响人类准备影片时的弹窗。

| HTTP 接口 | 数据 |
| --- | --- |
| `GET /api/viewing-settings`、`POST /api/viewing-settings` | 读取 `settings.skipIntroOutroPrompt`，用 `{ "skipIntroOutroPrompt": true }` 更新，默认关闭。 |
| `GET /api/library/skip-settings?collectionPath=合集路径`、`POST /api/library/skip-settings` | POST 接受 `{ collectionPath, skipConfig }`，两种方法都返回这两个字段。合集的 `skipConfig: null` 清除默认配置。 |
| `GET /api/media/:id/skip-settings`、`POST /api/media/:id/skip-settings` | POST 接受 `{ skipConfig }`，两种方法都返回 `{ skipConfig, skipRanges }`。单片的 `null` 表示继承，`{}` 表示显式不跳过。`GET /api/media` 的各影片条目同样包含这两个字段。 |

配置的 `intro` 和 `outro` 是 `{ fromMs, toMs }`，`middle` 是同结构的数组，时间使用整数毫秒。片尾的 `toMs: null` 表示至影片结束。生效区间按时间排序，包含 `{ kind, fromMs, toMs }`，左端包含、右端排除。合集改名会迁移其下的默认配置，解散会移除被解散那一层的配置，并保留移出的子合集配置。

## 对白与声音

保留的对白完整交付，并归入其开始时间所在的时间段。声音为本地 CoNeTTE 模型生成的描述文字，保留原始起止时间，按开始时间交付；模型分析较晚完成时，随后补入原来的时间段。描述可能涉及该区间内后续数秒的声音。

声音是可选准备项。准备状态区分未安装、未准备、处理中和失败；缺少声音资料时，已有画面和对白仍可使用。声音模型的描述可能出现误判，文本包含的是模型对音频的描述。

安装入口：Windows `Windows/setup-audio.ps1`，macOS `macOS/setup-audio.command`。使用独立 Python 3.10 环境及本地下载模型；配置保存在 `local-data/模型/声音描述/audio-model.json`。安装与运行细节见下方。

## MCP 工具：默认观影与可选扩展

影院 MCP 默认只暴露观影与互动所需的 4 个核心工具；回查历史台词与控制影院作为两个独立可选项，按启动参数开启：

| 分组 | 开关 | 入口 | 当前用途 |
| --- | --- | --- | --- |
| 一起观影 | 默认开启 | `open_watch_cinema_tick` | 接收最新观影内容、房间消息与设置变更提醒 |
| 一起观影 | 默认开启 | `cinema_inspect_frame` | 细看已收到的分镜图片 |
| 一起观影 | 默认开启 | `cinema_post_message` | 在房间交流与发送爆米花/可乐/碰杯互动 |
| 观影手记 | 默认开启 | `cinema_notebook` | 读写当前影片的共享笔记 |
| 回查历史 | `--with-history` | `cinema_read_window` | 按时间范围回查当前房间已播放的对白与声音 |
| 观影控制 | `--with-control` | `cinema_control` | 针对当前房间申请、查询或取消跳转建议 |
| 后台管理 | `--with-control` | `cinema_manage` | 影片发现、准备、任务进度、房间开启与结束 |

大工具采用 `{ action, parameters }`。`cinema_read_window`、`cinema_control` 与 `cinema_manage` 的 `end_room` 自动定位当前活动房间，无需手动传入 `roomId`。具体参数见 [MCP 技术参考](MCP%20技术参考.md)。

在网页端 **影院设置 → 连接 AI → MCP 客户端** 中，可分别勾选是否开启回查历史与控制影院，按客户端预设（Codex、Claude Desktop、Claude Code、Antigravity、通用 MCP）生成带本机绝对路径的配置，并复制随当前检查间隔动态更新的中立观影前 Prompt 模板。

### 自动观影

在 **影院设置 → 连接 AI → 自动观影** 保存 Watch Bridge 的取片间隔，默认每播放 6 秒，支持 0.5 至 30 秒。保存后当前会话下一次取片使用新值。播放器按实际影片时间上报进度。MCP 的基础 Prompt 和跟片变更提示仍采用「观影准备」里的 AI 查看间隔。

Codex App Server 和 ChatGPT Listener 共用连续观影间隔。ChatGPT Listener 另有「提前观影时长」，默认关闭，可在播放时让 Chat 提前看到 0.5 至 30 影片秒范围内的画面和对白。保存后当前放映生效。「自动连接方式」切换后会关闭旧方式，保留账号、模型和观影提示词等设置。两种方式各有观影开关，默认关闭。

启用 Codex App Server 后，影院按房间启动随片进程，以观众选中的影院档案署名。每场房间有独立的 Codex 聊天。影院重启且房间仍开放时，恢复已保存的同场绑定与观影进度。实际连接就绪后显示在线，影片暂停期间显示「在线 · 影片暂停中」。适配器共用 MCP 调用记录列表。

Codex 设置支持沿用本机 ChatGPT 登录或在影院数据根内独立登录，可选择模型并编辑影院自己的 AGENTS.md。开启并保存「Codex 观影模式」后，开房可填写本场开场白。影片开始播放后，开场白随第一批观影内容发给 Codex。登录经 Codex 的官方浏览器流程完成。房间、账号和模型以已建立的会话为准，观影间隔可随时更新。观众操作见 [Codex App Server 指南](../工具准备/Codex%20App%20Server.md)，适配器和独立运行方式见 [Watch Bridge](Watch%20Bridge.md)。

ChatGPT Listener 使用本机影院的独立 MCP 应用。影院和目前对话的卡片均开启后，影院会向这段对话交付观影资料。提示词可从出厂版本编辑，随本场第一次成功交付的资料送达，包括播放前的房间留言。发送时用「名字与档案」中的用户名替换 `{{viewerName}}`。默认提示在暂停中的跟片轮次集中整理值得记录的手记，播放中先聊电影，按点名再整理。用过旧版默认提示且还未收到这条手记约定时，下一次正常交付会附上手记提醒。开场白和续看资料随第一批播放资料送达。ChatGPT 工具范围保留观影、历史和控制分组。「主动观影（无需卡片）」可开放模型直接调用 `open_watch_cinema_tick` 读取已播放资料。主动观影、历史和控制默认关闭，工具范围可独立于自动连接方式保存，随后在 ChatGPT 刷新同一个插件。控制工具仅在当前对话的卡片已开始跟片时可用。暂停时 Listener 补齐到实际暂停点，明显积压时随追赶首批附一条说明。提前收到的内容仍留在 Chat，恢复播放时从已收到的位置继续。房间发言按影院实际播放时间显示。每批最多 16 张分镜。影院收到空参数回执满 1 秒后，已经就绪的下一批可立即领取。重启后可在原 ChatGPT 对话重新开启卡片，接续同一场仍开放的放映。在 ChatGPT 卡片全屏时，「AI 连接」显示与影院本机相同的全部连接及本次影院服务保留的历史调用。首次接入见 [ChatGPT Listener](../工具准备/ChatGPT%20工具配置.md)。

### 控制与设置的当前边界

控制请求保存当前房间、目标时间、原因和当前 seek 版本，两分钟过期；只保存在申请方 MCP 进程内，重启后丢弃。状态查询会核对房间及 seek 版本。当前没有用户批准入口、网页请求展示或自动执行跳转；用户仍需手动拖动播放器。

观影设置由用户在网页端维护。开场节奏通过影院设置生成的基础 Prompt 模板提供给 AI；观影中途修改查看间隔时，下一次 `open_watch_cinema_tick` 会自动附带简短变更提示。

## 连接、错误与缓存

MCP 通过本机 HTTP 连接影院，取消信号贯穿请求和图片读取。只读请求遇连接问题可安全重试；写操作结果不确定时返回 `WRITE_OUTCOME_UNKNOWN`，不自动重放。播放状态在交付中变化时，当前读取停止，下一次从新状态继续。

图片引用每个 MCP 进程最多保存 64 条，满后淘汰最早插入项；房间或 seek 重置会清理相关引用。影院地址按客户端缓存，显式刷新或连接异常时更新。上述引用和地址没有时间过期规则。

服务按影片固定编号定位片内的观影包。HTTP 图片响应为 `private, no-store`。旧 v2 高清图每次抽帧，没有应用级结果缓存。

## 代码位置

- `mcp/server.mjs`：组装与启动；`runtime/`：连接、协议、配置和校验。
- `mcp/viewing/`：会话、内容整理、补齐和观影提示；`mcp/tools/`：公开工具。
- `observer/worker.py` 调度观影包图片生成。播放时由 `src/delivery/viewing-package.mjs` 和 `src/visuals/storyboard-frame.mjs` 读取包内画面。
- `src/preparation/audio-descriptions.mjs`：声音资料；`src/visuals/viewing-cadence.mjs`：用户观影偏好。

性能数据见[实验记录](实验记录.md)。

## 安装、恢复与运行细节

影院设置中的声音描述默认开启，普通准备和升级沿用保存的声音选项。首次使用默认设置升级旧分镜时，缺少声音模型也可先准备画面和对白，之后补声音。准备前检查声音环境，缺少时提示安装；在设置中关闭后只准备画面与字幕。已有包可通过“继续准备”补齐，复用已有画面。

声音安装先复用兼容环境，或用 64 位 Python 3.10 在项目内创建声音环境，按需选择 uv 获取缺少的解释器。安装入口、自定义环境和自检说明见[安装与排错](../工具准备/安装与排错.md)。安装后刷新网页，在影院设置中开启声音描述，再选择“准备观影包”或“继续准备”。已有画面和选定对白轨继续复用。

声音默认使用 CPU。`OWC_AUDIO_DEVICE` 可覆盖设备，CUDA 需匹配 PyTorch；`OWC_AUDIO_PYTHON` 可指定兼容解释器。Windows 安装脚本不配置 GPU。当前模型环境为 Python 3.10、CoNeTTE 0.4.0、PyTorch 1.13.1、Transformers 4.30.2，与视觉环境分开维护。

声音使用第一音轨、单声道 32 kHz；默认每段 10 秒，配置 `segmentMs` 可取 2–20 秒。模型只接收音频，每个准备任务内保持常驻，任务结束后退出。已完成块保存 `audio.json` 及配置版本；重试复用匹配的检查点，模型、片段长度等配置改变后重新准备相应声音块。CLI 可使用 `npm run observer:precompute -- --input path/to/film.mp4 --audio`。

模型权重和准备资料位于本地忽略目录。`LOCAL_DATA_ROOT` 可指定数据根目录，音频资源位于其 `模型/声音描述/audio-resources`，spaCy tokenizer 安装在独立环境内。模型说明见 [CoNeTTE](https://github.com/Labbeti/conette-audio-captioning)。

## 内容交付与故障处理细节

交付流程是收集内容、读取图片、核对房间和播放位置，再提交已交付游标。一个 tick 正在运行时，同进程第二个 tick 返回等待。单张图片失败保留其他图片与文字；尚未准备的内容显示等待准备，已播放但尚未发送完的内容留到下一次调用。

`OPEN_WATCH_CINEMA_CATCHUP_BUDGET_MS` 可限制补页时间，`OPEN_WATCH_CINEMA_IMAGE_BUDGET_BYTES` 可限制单次图片总量。未指定时沿用现有页数、条数等边界。超出图片预算的剩余内容保留引用，后续交付；主动取消时保留原进度。客户端取消不回滚已经在后台发生的写入，结果不确定时先查询状态。

连接时检查影院健康与兼容能力，`cinema_manage` 的 `status` 操作显式刷新状态。普通只读连接故障重新发现后最多重试一次；业务错误直接返回。错误信息区分影院不可达、不兼容、播放变化、资源不可用与写入结果不确定，调用方按具体状态继续。

播放设置保存在 SQLite；tick 使用当次设置快照，设置 revision 改变后提示一次。更新影院或 MCP 代码后需重启相应进程，工具列表变化后刷新宿主缓存。用户跳转用单调增长的 `seekVersion` 同步，各 AI 保留独立消息和观影游标。

视觉检测使用 192×108 小图，按场景变化、运动、清晰度、曝光及静态间隔选帧；安静场景也有稀疏采样。切换影片分镜样式时单独准备新包，再校验、切换；可复用时沿用时间点、对白和声音，从原片重新生成分镜，跟片固定读取已准备样式。高档位增加传输量和图像处理成本。完整观影仍需结合对白、声音和实际图片理解。

新准备的画面动态里，整幅画面的运动量达到门槛，且有效运动有一致的主要方向时，才会附上方向。各方向彼此抵消时，仍可收到「画面出现明显运动。」

## 后台源码目录

`src/media/` 负责影片扫描、播放兼容、字幕和视频范围读取；`src/preparation/` 负责准备计划、任务执行及视觉和声音处理的调用；`src/delivery/` 负责观影包和按时间交付；`src/visuals/` 负责图片读取、选图与观影偏好；`src/storage/` 负责影片和房间的数据库记录。

右侧片库每行显示两个合集文件夹，影片卡每行一张。片库以无外框的大文件夹图标显示合集，点击图标进入。铅笔按钮可为整个合集改名，子合集、影片编号及其关联记录随原有目录结构继续使用。点击「整理」展开批量选择栏（按当前可见影片全选）与片卡左侧的选片框。片卡右侧并排显示铅笔和齿轮，用于重命名和打开影片设置；「导入影片」选择视频文件。整理模式的影片齿轮分别列出内嵌和外挂字幕，可补提文字轨或按选中的轨道清理文件。新片归夹时按影院当前勾选的简中、繁中和英文自动提取。设置变动只影响之后的新片。影片的提取任务在本机后台运行，重新连接可接回进度；服务中断后可重试未提交的批次。已完成观影包从包内读取自己的对白。播放器列出本片实际可用的字幕轨，「＋ SRT/VTT」可临时添加本机字幕。

银幕下方的待试播片卡接近方形，确认可播放后高度随内容收紧。右侧片库使用贴合栏宽的列表卡。卡片右上角的 × 打开释放空间弹窗。卡片显示当前可做的操作。标有「待试播」的影片可先播放，画面和声音正常后点「确认可播放」。遇到问题点「检查播放」，修复后按「请重新试播」再次核对。AI 资料按状态显示「准备观影包」「升级」「继续准备」或「观影包设置」。待试播和尚未准备使用淡蓝提示，播放或准备失败时显示错误。

房间侧栏和影片手记各有导出入口。交付层从当前房间消息或影片共享手记生成同一份内容，再输出离线 HTML 或紧凑的 UTF-8 纯文本。房间 HTML 使用窄票根版式，按电影时间排列聊天和互动。导出文件由浏览器保存，影院数据库继续保存原始记录。

每个后台业务目录的 `index.mjs` 提供对外公共入口。根后台和业务脚本从对应入口导入功能，目录内部调整时可在入口维护导出路径。组内及准备、交付、图片之间的内部协作保留具体模块引用，避免公共入口形成循环依赖；单元测试可直接引用被测文件。

### 后台总调度

根目录 `server.mjs` 按配置与共享状态、功能调度、HTTP 公共方法、影片与准备任务、文件交付、功能接口、启动关闭分区。

接口分为六组：系统状态与观影设置、影片库、房间与交流、AI 观影、资料准备、文件服务。新接口放在对应的 `handle…Routes` 函数中；新增功能组在 `routeGroups` 中登记。处理函数接收同一个请求上下文，处理了请求返回 `true`，未匹配返回 `false`。视频流交付也使用这个返回约定。

数据库、媒体索引和准备任务表由应用统一持有。HTTP 请求的取消、异常处理和监听清理由公共请求入口负责；具体的观影计算、包读取、图片处理和准备流程继续调用 `src` 中的功能模块。

### 升级已有观影包

旧包按观影包格式识别，片卡显示「升级」。本地试验过的 v3 分镜如需重做，可在片卡中只清理观影包，再选择画质重新准备。打开本片观影包设置，预选已有档位和可用的原对白轨；没有档位记录时预选均衡。点「确认升级」后在独立目录准备新版并校验，再切换正式包。当前分镜的包按完成情况显示「继续准备」或「观影包设置」。

升级期间保留原包，禁止为同一影片开启房间、修复播放文件或重复启动准备任务。已有活动房间需先结束。原影片不变；新版完整生成、校验并成功切换后，旧包移入系统回收站，不再保存在项目内。若系统无法安全回收则保留旧包并显示提示，不做永久删除。已有可用的对白或声音未能在新版中生成时，升级停止，原包继续保留。

生成失败可再次点击升级。未完成的临时资料保留在对应升级目录，再次升级会新建任务。服务在切换中断后启动时，会检查恢复记录；正式包目录缺失而原包备份存在时，恢复原包。失败临时资料和系统回收站仍会占用磁盘空间。升级界面独立显示新版准备百分比、阶段与已处理电影时长；旧包状态单独展示，校验并切换完成后直接回到新版已就绪状态，仅在旧包未能自动回收或升级失败时保留提示。

影片列表加载时重新检查包清单。手动移除整个包后，刷新页面或影片列表即可显示“未准备”，随后可重新准备。只删除部分图片或分块时，清单可能仍存在，缺失内容在读取时报告。影片卡片的 × 会预览文件占用、房间和手记条数。视频、字幕、观影包可独立清理。「观影记录」将该片的所有房间、聊天和共享手记作为一项清理。合集铅笔提供改名、解散、删除空目录和按同一组勾选批量清理。历史页按场删除时，同一影片还有其他房间便保留小本本，最后一场的确认框会显示将一起删除的手记条数。

### 房间消息

发言署名和可点击的电影时间排在玻璃气泡外。片源可用时，点击时间跳到当时的画面；互动动作居中显示。

网页通过事件流接收消息变更通知，随即补取房间消息，按消息 ID 去重。重新连接时补齐历史；连接正常时每 30 秒兜底刷新，连接中断或浏览器不支持事件流时每 3 秒刷新。互动设置也通过事件通知同步，重连和拖动进度不会重复播放已接收互动的动画。普通 MCP 客户端在下一次 tick 接收房间消息。两种自动观影方式都可在暂停时因新消息唤醒。

### 零食与饮料互动

侧栏聊天框左下角与底栏快捷输入条最左侧均内嵌小礼盒图标入口，点击展开共用的浮动互动面板，收拢“递爆米花”“递可乐”“碰杯”等互动动作（发送后保持面板打开，点外部、再次点击图标或按 Esc 关闭）。动作以互动卡片记在房间消息中，保留发送者和当时的电影时间。普通模式在聊天栏显示短动画；影院全屏时在电视画面中心短暂显示。动画不暂停影片、不抢输入焦点、不拦截画面操作，并适配系统的减少动态效果设置。

“互动”总开关是影院级共享设置，保存后重启仍有效。关闭时隐藏互动入口、卡片与动画，拒绝人类和 AI 发送互动；普通聊天保持可用。历史互动记录仍保存，重新开启后可查看，历史动作不会自动补播动画。其他浏览器收到事件通知后同步开关，断线时通过兜底刷新同步。

AI 使用 `cinema_post_message` 的可选 `interaction` 参数发送动作；人的互动随 AI 下次 tick 送达。互动按消息游标交付，拖动影片进度后仍保留原电影时间；连续调用使用更新后的游标不会重复交付。连接保留游标时接续读取；新会话清空游标会按现有消息机制重新读取历史。


### 观影小本本

一个影片 ID 对应一本手记。本地 `local-data/影院记录/open-watch-cinema.sqlite` 中的 `notebook_revisions` 是权威内容；分区文本与书页按同一组条目生成。人工和 AI 都能写人物（含称呼、小传和可选外貌特征）、关系、剧情、疑问、答案和随记。字段归属用于合并无冲突的改动；同时修改同一字段会提示冲突。播放回拖、换房间、原有的影片移除操作沿用手记保留策略。

影院参与者用稳定标识区分，显示名称集中在 `cinema_participants`。一座影院共享一个观众署名，各 AI 单独署名。小本本的创建者、修改者和可分开修改的字段引用参与者。人工修改事件单独存在 `notebook_change_events`，tick 通过每个客户端自己的游标领取；浏览器通过房间通知刷新。窗口外观位置保存在浏览器，小书展开时按需读当前影片的笔记。「人物关系」页的布局由 `public/notebook-graph.js` 在浏览器里计算：确定性的力导向排布（相同人物、关系和宽度得到相同位置），有关系的人互相靠近，人物之间保留关系标签的空间；连线遇到旁人会弯开，关系标签沿线找不压人物和其他标签的位置。首字圆形徽章和名字按图区宽度在 0.72 到 1 倍之间缩放，图区变宽变窄时重新排布，人多时图区向下延伸滚动。翻开小本本的轻互动继续使用已有的房间互动开关。

本本内容只按需读取，没有每 tick 重发或定时提醒。小本本、模型权重和实验资料都在 Git 忽略的本地数据目录。
