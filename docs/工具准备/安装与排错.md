# 安装与排错

## 安装影院

| 想做什么 | 需要准备什么 |
| --- | --- |
| 播片、看字幕、发弹幕、记笔记 | Node.js 24 或更新版本、FFmpeg（含 FFprobe）和可播放该影片的浏览器。推荐 Chromium 浏览器。 |
| 准备 AI 分镜和对白 | Python 3.11 或更新的兼容环境、OpenCV 4.10–4.x、NumPy。对白来自影片可提取的文字字幕。 |
| 让 AI 读到环境声和音乐描述 | 64 位 Python 3.10.x、CoNeTTE 0.4.0 及配套资源。影院为声音依赖单独建环境。 |

### 第一次完整安装

先解压或克隆项目，在项目根目录打开终端。用 `node --version` 检查 Node，达到 24 就可以运行安装入口。Mac 缺 Node 可用 `brew install node`；Windows 可用 `winget install --id OpenJS.NodeJS.LTS -e`。已有自己的 Node 版本管理器也可以直接选用。完整入口也能在缺 Node 时提示通过已有的 Homebrew 或 winget 安装。手工安装后重新打开终端。

**macOS**

```bash
bash macOS/setup-all.command --plan
bash macOS/setup-all.command
```

**Windows（PowerShell）**

```powershell
.\Windows\setup-all.bat --plan
.\Windows\setup-all.bat
```

第一条只列计划。看清沿用的解释器、需要补的工具、模型和保存位置后，第二条进入安装。按回车退出，输入 `y` 执行。Mac 上优先用已有的 Homebrew 补缺少的工具。Windows 会列出对应的 winget 命令；确认后通过已有的 winget 安装。也可以退出，先用自己惯用的方式准备好再继续。脚本使用当前账号。

**如果你只想播放**，装好 Node 和 FFmpeg 就可以按[观影指南](../观影须知/观影指南.md#启动影院)启动。Mac 上用 `brew install ffmpeg`；Windows 可用 `winget install --id Gyan.FFmpeg -e`。用 `ffmpeg -version` 和 `ffprobe -version` 确认两条命令都可用。

### 选择已有环境

| 我的电脑上有什么 | 怎样选择 |
| --- | --- |
| 已有一整套视觉或声音环境，希望直接拿来用 | 设置 `OWC_OBSERVER_PYTHON` 或 `OWC_AUDIO_PYTHON` 为环境内 Python 可执行文件的完整路径。安装脚本验证依赖，在该环境中运行自检。外部环境的包由你维护。启动影院时也使用同一变量。 |
| 有合适版本的 Python，想让影院单独装依赖 | 默认会查找兼容的解释器。需要指定路径时，首次创建环境前设置 `OWC_OBSERVER_BASE_PYTHON` 或 `OWC_AUDIO_BASE_PYTHON`。影院把依赖装进 `observer/.venv` 或 `observer/.conette-venv`。 |
| 已经用这份项目装过 | 重跑会检查已有项目环境、模型与资源。已完成的部分可以复用。改用另一套已配好的环境时，用第一行的变量选择。 |
| 电脑上缺 Python 3.10，或 Homebrew 的安装条件不满足 | 可以自己准备 64 位 3.10，也可以把 `--uv` 加在完整安装命令后面。uv 能单独取得缺少的 Python，保留你的日常默认版本。 |

例如，下面分别演示“复用已有视觉环境”和“使用自己的 Python 3.10 创建声音环境”。只设置你需要的变量，把示例路径换成实际路径。

```bash
export OWC_OBSERVER_PYTHON="/path/to/your/visual-env/bin/python"
export OWC_AUDIO_BASE_PYTHON="/path/to/python3.10"
bash macOS/setup-all.command --plan
```

```powershell
$env:OWC_OBSERVER_PYTHON = 'C:\path\to\visual-env\Scripts\python.exe'
$env:OWC_AUDIO_BASE_PYTHON = 'C:\path\to\python3.10.exe'
.\Windows\setup-all.bat --plan
```

如果在 venv 或 Conda 环境里运行完整入口，已有项目环境优先；首次安装会检查当前激活的环境，兼容就直接使用。以后在同一环境中启动影院，或显式指定它的解释器。

外部环境的变量对当前终端及其子进程生效，用同一终端运行启动脚本即可。直接从 Finder 或资源管理器双击时，独立窗口使用它自己能看到的环境。Windows 的声音分项也支持原有的 `-Python` 参数来指定创建环境用的解释器。

### 只装一项，或从某一项重试

| 功能 | macOS | Windows |
| --- | --- | --- |
| OpenCV 分镜 | `bash macOS/setup-observer.command` | `.\Windows\setup-observer.bat` |
| CoNeTTE 声音描述 | `bash macOS/setup-audio.command` | `.\Windows\setup-audio.ps1` |

声音环境通过合成的 10 秒音频进行离线模型推理，得到非空描述后写入 `local-data/模型/声音描述/audio-model.json`。视觉安装输出里可查看 `opencvAvailable` 和 OpenCV 实际版本。批量部署可在已看过计划后使用 `--yes`。PowerShell 的声音脚本对应 `-Plan`、`-Yes`、`-UseUv`，也可以直接用 `node scripts/preparation/setup.mjs audio`。

声音模型、离线资源与配置集中放在 `local-data/模型/声音描述/`。自定义数据根时，在安装和启动时设置同一个 `LOCAL_DATA_ROOT`。备份时同时保存影片仓库和影院记录目录。

## 安装排错

从这里选择你的系统：[macOS 安装](#mac-install-help) · [Windows 安装](#windows-install-help) · [两端通用的观影问题](../观影须知/观影指南.md#常见观影问题)。

<a id="mac-install-help"></a>

### macOS 安装

**Homebrew 装好了 FFmpeg，但 Python 3.10 提示需要 Command Line Tools。** 先用 `ffmpeg -version` 和 `ffprobe -version` 核实播放工具，再运行 `bash macOS/setup-all.command --plan` 看剩下的项目。有自己的 64 位 Python 3.10 时，通过 `OWC_AUDIO_BASE_PYTHON` 指定它；也可以运行 `bash macOS/setup-all.command --uv` 取得声音解释器。已有的 FFmpeg 可直接复用。

**Apple 芯片上装好了声音包，离线声音自检失败。** 在 macOS 27 的实测中，Torch 1.13.1 的 arm64 安装包在内部把平台写成了 x86_64，单独运行 `pip check` 会报告这一项。影院针对这一个提示实际运行原生 Torch 和 TorchAudio 运算，然后继续做 CoNeTTE 离线推理。另一个可辨认的报错是 SciPy 加载 `_spropack` 时提示 `__thread_bss`；影院为 Apple 芯片选择了已通过推理的 SciPy 1.13.1。使用更新后的入口 `bash macOS/setup-audio.command` 重试声音，保留现有模型缓存。只有最后看到离线推理通过，才算声音可用。

**终端里安装成功，双击启动却找不到我的环境。** 如果用 `export OWC_OBSERVER_PYTHON=…` 或 `export OWC_AUDIO_PYTHON=…` 选择了外部环境，在同一终端启动 `bash macOS/start.command`。若只用带 `BASE` 的变量创建了项目环境，之后可直接用项目内环境。

<a id="windows-install-help"></a>

### Windows 安装

**安装到一半，提示找不到 ffprobe 或 Python。** 在新打开的 PowerShell 里执行 `Get-Command ffmpeg,ffprobe` 和 `.\Windows\setup-all.bat --plan`。原窗口可能仍使用安装前的 PATH。已有 64 位 Python 3.10 时可对声音单项运行 `.\Windows\setup-audio.ps1 -Python 'C:\实际路径\python.exe'`。这会用它创建项目声音环境；若已有完整环境，设置 `$env:OWC_AUDIO_PYTHON` 指向其中的 `python.exe`，在同一窗口安装并启动。

**PowerShell 的执行策略拦住了声音分项脚本。** 在项目根目录运行 `node scripts/preparation/setup.mjs audio` 即可进入同一安装流程，沿用电脑原有的执行策略。要补视觉单项，用 `.\Windows\setup-observer.bat`。重试时保留已完成的环境、权重和影片。
